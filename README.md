# 플래시 난투 · Flash Versus

「고추참치송」, 「해킹송1」, 「감자튀김송」, 「썩던콩」, 「에메랄드 소드」의 원본 SWF에서 벡터 그림과 음원을 추출해 만든 브라우저 대전게임입니다. 흰 종이, 손글씨, 삐뚤한 선으로 원본의 분위기를 이어갑니다.

## 실행

Node.js 20 이상에서 프로젝트 폴더를 열고 실행합니다. 처음 한 번 WebSocket 서버 의존성을 설치합니다.

```powershell
npm ci
npm run dev
```

브라우저에서 **http://127.0.0.1:5173**에 접속하세요. VS Code에서는 **F5 → `vs: 플래시 난투`**로 Edge 디버깅을 시작할 수 있습니다. `index.html`을 파일로 직접 열면 모듈과 음원 로딩이 제한되므로 서버를 사용합니다.

## Vercel에서 공유하기

**서로 다른 기기에서 온라인 대전을 하려면 Vercel의 게임 화면과 별도의 Node 온라인 서버를 모두 배포합니다.** Vercel 계정과 온라인 서버 호스팅 계정이 필요합니다. `deploy/render.yaml`은 Render에서 이 프로젝트의 Node 서버를 배포하기 위한 설정입니다. Vercel CLI가 루트의 Render 설정을 자동으로 가져오지 않도록 별도 폴더에 둡니다.

1. Vercel에 아래 명령으로 로그인하고 프로젝트를 연결해 게임 주소를 발급받습니다. Git 저장소 없이도 Vercel CLI로 클라이언트를 배포할 수 있습니다. 아직 온라인 서버를 연결하지 않았으므로 이 주소는 다음 설정을 마친 후 공유합니다.

```powershell
npx vercel login
npx vercel --prod
```

2. 프로젝트를 Git 저장소에 올리고 Render에서 Blueprint 경로를 `deploy/render.yaml`로 지정해 서비스를 만듭니다. 설치 명령은 `npm ci --omit=dev`, 실행 명령은 `npm start`입니다. `ALLOWED_ORIGINS`에는 1단계에서 발급받은 실제 Vercel 게임 출처(`https://프로젝트.vercel.app`, 끝의 `/` 없이)를 입력합니다. 여러 출처는 쉼표로 구분합니다. 생성된 HTTPS 서버 주소의 `/health`에서 정상 응답을 확인합니다. 이미 생성된 서버가 있으면 해당 서버를 재사용합니다.
3. Vercel 프로젝트의 **Settings → Environment Variables**에서 프로덕션에 `ONLINE_SERVER_URL=https://온라인서버주소/online`을 설정한 뒤 다시 배포합니다. `wss://`도 지원하며 경로를 생략하면 `/online`을 사용합니다. 주소에는 사용자 정보나 `#` 조각을 넣을 수 없습니다. 이 값은 브라우저에 공개되는 접속 주소이므로 비밀 토큰을 포함하지 않습니다.
4. 두 기기에서 같은 Vercel 주소를 열어 방 만들기·코드 참가·랜덤 매칭·대전 시작을 확인한 뒤 공유합니다. 초대 링크도 Vercel 게임 주소를 사용합니다. 커스텀 도메인이나 미리보기 주소를 사용할 때는 해당 출처도 서버의 `ALLOWED_ORIGINS`에 추가합니다.

Render 설정은 무료 인스턴스 1개를 사용합니다. [무료 서버는 15분 동안 접속이 없으면 절전되고 다시 시작하는 데 약 1분이 걸릴 수 있습니다](https://render.com/docs/free). 외부 서버의 첫 연결은 최대 90초 기다립니다. 방·경기·매칭은 메모리에 저장되므로 재배포나 서버 재시작 시 초기화되며, 현재 서버를 여러 인스턴스로 늘리면 같은 방의 플레이어가 나뉠 수 있습니다. 항상 1개 인스턴스로 운영합니다.

Vercel CLI를 처음 실행할 때 계정과 새 프로젝트를 선택하고 현재 폴더를 사용합니다. `vercel.json`이 **Other** 프레임워크, `npm run build:vercel`, 출력 폴더 `dist-static`을 지정합니다. Git 저장소를 연결해 Vercel 대시보드에서 가져올 때도 같은 설정을 사용합니다. 프로젝트 연결 정보는 `.vercel/`에 저장되며 Git과 업로드에서 제외됩니다. 인증 토큰을 프로젝트 파일에 넣지 마세요.

`npm run build:vercel`은 클라이언트와 게임 에셋만 복사합니다. 온라인 서버 주소를 설정하기 전에는 온라인 대전을 준비 중으로 표시하며 **혼자서 플레이·연습장·같은 기기 2인**은 사용할 수 있습니다. `.vercelignore`는 추출 도구와 중간 파일의 업로드를 제외합니다. 기존 Node 서버용 `npm run build`는 그대로 사용할 수 있습니다.

Vercel Functions 자체는 [WebSocket 연결을 지원](https://vercel.com/kb/guide/do-vercel-serverless-functions-support-websocket-connections)합니다. 다만 현재 온라인 서버는 메모리에 방과 대전 상태를 보관하므로 여러 함수 인스턴스와 실행 시간 제한에 맞춘 구조 변경이 필요합니다. 이 Vercel 설정은 정적 게임 클라이언트를 배포하며 온라인 서버는 별도로 연결합니다.

## 게임 진행

스크롤 없이 하나의 게임 화면 안에서 **모드 선택 → 1P 캐릭터 → 상대 캐릭터 → 무대 → 대전** 순서로 진행합니다. 카드를 클릭하면 결정과 함께 다음 단계로 넘어갑니다.

- **혼자서 플레이**: 1P와 CPU 캐릭터를 차례로 고릅니다.
- **멀티플레이**: 같은 게임 화면에서 온라인 대전 또는 같은 기기 2인을 고릅니다. 온라인은 방 만들기·코드 참가 → 각자 캐릭터 선택 → 방장 무대 선택 → 대전 순서입니다.
- **연습장**: 내 캐릭터와 연습 상대를 고릅니다.

방향키 또는 A/D로 선택하고 Enter/J로 결정합니다. Esc/K는 이전 단계로 돌아갑니다. 무대를 결정하면 VS 화면 뒤에 대전이 시작되며 Enter로 VS 화면을 건너뛸 수 있습니다. 대전 중 Esc는 일시정지입니다. 일시정지·승리 화면에서 캐릭터 재선택 또는 재대전으로 이어집니다.

조작법·설정·원본 보관함은 게임 안의 메뉴로 열립니다. 모바일의 터치 버튼도 대전 화면 안에 표시됩니다. 캐릭터 7명은 데스크톱에서 한 줄, 휴대폰 세로 화면에서 두 줄로 배치합니다. 텍스트 대사나 시작 구호·부제는 표시하지 않습니다.

첫 클릭이나 키 입력 후 메뉴 배경음악이 시작됩니다. `ost-1/`의 **고추참치 MR → The Queen of Heart'99 · 長岡志保 → Virtual On · Into the Blue Sky** 3곡을 전체 길이로 차례로 반복합니다. 캐릭터·무대 선택, 온라인 대기실, VS 화면까지 이어지며 대전이 시작되면 음악이 멈추고 캐릭터 음성만 재생합니다. 음악 크기와 켜기·끄기는 기존 설정에서 조절합니다.

## 들어 있는 게임

- 원본 등장인물 7명: 참치맨, 해킹범, 밥도둑, 격노맨, 감자맨, 썩던콩, 에메랄드. 이름은 게임에서 구분하기 위한 별칭입니다.
- CPU 대전 3단계, 같은 키보드로 하는 로컬 2인 대전, 시간·기력 제한이 없는 연습장.
- 기본 60초·2선승. 30/60/99초와 1/2/3선승으로 변경할 수 있습니다.
- 약·강 공격, 점프, 대시, 가드, 잡기, 캐릭터별 투사체, 기력 100을 사용하는 초필살기.
- 캐릭터마다 원본 포즈·소품·음원을 사용하는 추가 기술 2개, 총 14개. 추가기는 기력 없이, 강화기는 기력 25로 사용합니다.
- 명중한 약 → 약 → 강 → 필살 연계와 필살 → 초필살 연결. 상대 경직이 풀리면 콤보와 피해 보정이 초기화되며, 가드한 공격은 명중 취소 연결을 허용하지 않습니다.
- 투사체는 발사한 공격의 명중을 확인하며, 다른 공격을 시작한 뒤 도착한 투사체가 새 공격의 취소 조건을 열지 않습니다. 다단 히트·연사·대공 투사체·추격 잡기를 지원합니다.
- 냉장고 앞, 컴퓨터 방, 흰 종이 무대. 배경 소품도 원본에서 추출했습니다.
- 원본에서 자른 선택·기술·피격·승리 음성과 대전 전 메뉴 배경음악. 음악·효과음 크기를 따로 조절할 수 있습니다.
- 터치 버튼, 표준 Gamepad API 입력, 전체화면, 창 전환 시 자동 일시정지, 브라우저 설정 저장.
- 게임 안의 기술표에서 피해량·조작법을 확인하고 원본 음원 구간을 들을 수 있습니다.

| 추가 캐릭터 | 원본 | 필살기 | 초필살기 |
| --- | --- | --- | --- |
| 감자맨 | 감자튀김송 | 감자튀김 투척 | 감자 돌진 |
| 썩던콩 | 썩던콩 / Southern Cross 패러디 | 콩알 투척 | 기타 러시 |
| 에메랄드 | 에메랄드 소드 | 어묵 투척 | 불새 소환 |

온라인 대전은 계정 없이 6자리 방 코드로 참가합니다. 클라이언트와 Node 서버가 같은 프로젝트에서 실행되며, 그림·음원·글꼴은 외부 CDN 없이 로드합니다.

## 조작

| 동작 | 1P | 2P |
| --- | --- | --- |
| 좌우 이동 | A / D | ← / → |
| 점프 / 가드 | W / S | ↑ / ↓ |
| 약 / 강 공격 | J / K | 1 / 2 |
| 필살기 / 초필살기 | L / I | 3 / 0 |
| 대시 | Space | 오른쪽 Shift |
| 잡기 | U 또는 J+K | 4 또는 1+2 |
| 시작 / 일시정지 | Enter / Esc | 공통 |

추가 기술은 다음 입력으로 사용합니다. 기존 6개 터치 버튼을 함께 누르거나 패드 버튼을 함께 눌러도 같습니다.

| 동작 | 1P | 2P | 패드 |
| --- | --- | --- | --- |
| 캐릭터 추가기 | S+K 또는 K+L | ↓+2 또는 2+3 | ↓+B 또는 B+X |
| 캐릭터 강화기 (기력 25) | J+L | 1+3 | A+X |
| 강화기 방향 커맨드 | 상대 방향으로 ↓↘→ + J | 상대 방향으로 ↓↘→ + 1 | ↓↘→ + A |

동시 입력 허용 시간은 50ms이며, 입력은 180ms 동안 보관합니다. 방향 커맨드는 상대가 있는 방향을 기준으로 350ms 안에 입력합니다. 명중 뒤 약을 한 번 더 누르면 연속 약공격으로 이어집니다. 이후 강공격 → 필살기 또는 추가기 → 초필살기로 연결할 수 있습니다. 가드·빗나감으로는 취소 연결이 열리지 않습니다.

| 캐릭터 | 추가기 | 강화기 |
| --- | --- | --- |
| 참치맨 | 대공 커터 | 참치캔 연속 투척 |
| 해킹범 | 돌진 킥 | 파일 다중 발사 |
| 밥도둑 | 추격 잡기 | 밥그릇 연계 |
| 격노맨 | 대공 불꽃 | 근거리 폭발 |
| 감자맨 | 감자 돌진 후속타 | 감자튀김 확산 투척 |
| 썩던콩 | 기타 연타 | 무지개 마술 |
| 에메랄드 | 김밥 연속 타격 | 어묵 연사 |

각 기술의 피해와 입력은 게임 안 기술표에 표시됩니다. 연속 타격에는 90%씩, 최저 50%까지 피해 보정이 적용됩니다. 추가기는 90프레임, 강화기는 125프레임의 재사용 간격이 있어 같은 기술을 무한히 취소 연결할 수 없습니다. 초필살기 발동은 일반 입력 시 18프레임, 명중 취소 연결 시 10프레임입니다.

2P 숫자는 숫자열과 숫자패드 모두 지원합니다. 상대에게서 뒤로 이동할 때도 지상 자동 가드가 적용됩니다. 잡기는 가드를 무시하지만 공중에는 닿지 않습니다.

게임패드 메뉴는 좌우 방향으로 선택, A/Start 결정, B 이전입니다. 대전은 스틱·십자키 이동, 십자키 위 점프, A/B 약·강, X/Y 필살·초필살, LT/RT 가드, LB 잡기, RB 대시, Start 일시정지입니다. 연결된 첫 번째 패드가 1P, 두 번째가 2P입니다.


## 온라인 대전

멀티플레이 → 온라인 대전에서 방을 만들거나 방 코드 6자리로 참가합니다. 대기실에서 코드 또는 초대 링크를 복사할 수 있습니다. 두 사람이 입장하면 각각 자기 캐릭터를 선택하고, 방장이 무대와 경기 규칙을 결정합니다. 온라인에서는 두 기기 모두 **WASD / J K L I / Space / U 또는 첫 번째 게임패드**로 자기 캐릭터를 조작합니다. 터치 버튼도 자기 자리로 전달됩니다.


온라인 대전 화면의 **랜덤 매칭 → 상대 찾기**를 누르면 같은 서버에서 대기 중인 상대와 자동 연결됩니다. 대기실을 따로 열거나 방 코드를 입력할 필요 없이, 매칭 성사 후 기존 캐릭터·무대 선택으로 이동합니다. 기본 경기 규칙은 60초·2선승이며 무대 선택 단계에서 방장이 조정할 수 있습니다.

- 서버가 대기 시간을 최대 **180초(3분)**로 제한하며 화면에 남은 시간을 표시합니다.
- 중복 요청은 대기 시간을 늘리지 않습니다. 취소·연결 종료·수동 방 참가 시 대기열에서 제거됩니다.
- 3분 안에 상대를 찾지 못하면 대기를 종료하고 **다시 찾기 / 이전으로**를 표시합니다. 자동 재등록은 하지 않습니다.
- 취소가 처리된 사람이나 이미 방에 들어간 사람은 새 상대와 연결되지 않습니다.
- 랜덤 대전 상대가 나가면 같은 대기실의 **새 상대 찾기**로 다시 대기할 수 있습니다. 같은 상대와의 재대전은 기존처럼 양쪽 동의가 필요합니다.

서버가 60Hz로 전투 판정·기력·피해·라운드·승패를 계산하고 30Hz로 두 클라이언트에 같은 결과를 전송합니다. 클라이언트는 위치를 보간해 그리며, 상대의 입력이나 체력을 직접 수정할 수 없습니다. 온라인 중 메뉴를 열거나 창을 전환해도 상대의 경기는 계속되며, 내 입력은 중립으로 정리됩니다.

연결이 끊기면 경기를 멈추고 15초 동안 같은 자리를 보관합니다. 같은 탭을 새로고침해도 세션에 저장된 접속 정보로 복구합니다. 시간이 지나면 남은 플레이어가 같은 대기실에서 새 상대를 받을 수 있고, 방장이 나가면 남은 플레이어가 방장이 됩니다. 재대전은 두 사람의 동의가 필요합니다.

다른 기기에서도 **같은 서버 주소**로 접속해야 합니다.

- 같은 네트워크에서는 서버 실행 시 출력되는 `Network play` 주소를 사용합니다. `127.0.0.1`은 각 기기 자신을 가리킵니다.
- 외부 인터넷에서는 접근 가능한 Node 서버 주소가 필요합니다. 호스팅 환경의 `PORT`를 사용하며 기본 수신 주소는 `0.0.0.0`입니다.
- HTTPS 뒤에서 운영하면 프록시가 `/online`의 WebSocket 업그레이드를 전달해야 합니다. 브라우저는 자동으로 WSS를 사용합니다.
- 정적 파일만 제공하는 호스팅에서는 온라인 서버가 동작하지 않습니다.

`npm run build`는 클라이언트와 서버, 원본 에셋, 의존성 잠금 파일을 `dist/`에 복사합니다. 배포 서버에서 `dist/`를 열고 `npm ci --omit=dev`, `npm start`를 실행합니다. 필요하면 `HOST`, `PORT`, `ALLOWED_ORIGINS` 환경 변수로 수신 주소·포트·허용 출처를 지정할 수 있습니다.

### 에셋 다시 추출하기

게임 실행에는 아래 도구가 필요 없습니다. 에셋을 수정하거나 원본에서 다시 추출할 때만 사용합니다.

1. Java 17 이상, Python 3, ffmpeg를 준비합니다.
2. `tools/fetch-sources.ps1`로 보관소 SWF, Google Fonts의 Gaegu, JPEXS FFDec 26.4.0을 받습니다.
3. `tools/extract-assets.ps1`로 벡터·음원·타임라인 XML을 추출합니다. ActionScript를 실행하지 않습니다.
4. `python tools/build-assets.py`로 게임용 SVG 42개, 음원 구간 34개, 출처 매니페스트를 재생성합니다. 에메랄드 소드의 Sprite 9 안에 있는 스트리밍 MP3도 XML에서 자동 복원합니다.

음성 구간과 캐릭터 영역은 `tools/build-assets.py`, 캐릭터 능력치와 포즈 연결은 `src/data.js`에서 조정합니다. 선택·필살기·승리 음성은 약 3.5~5.6초, 피격음은 1.4~1.5초로 원본의 앞뒤를 더 담았습니다. 일반 기술과 피격음은 재생 중인 캐릭터 음성을 끊지 않고, 초필살기와 승리 음성은 우선 재생합니다. SWF에서 추출한 구간은 브라우저의 MP3 디코더 차이를 피하기 위해 PCM WAV로 저장하며, 원본 SWF도 함께 보존합니다.

선택·전투 음성은 플레이어별 재생 슬롯을 공유해 각자 한 번에 하나씩만 재생합니다. 미리듣기는 다른 음성과 겹치지 않으며, 화면·라운드 전환 시 재생 중이거나 로딩 중인 음성을 정리합니다. 반복된 음악 요청도 하나의 배경음악만 재생합니다.

34개 WAV는 EBU R128 측정으로 음성 **−18 LUFS**, 배경음악 **−20 LUFS**에 맞추고, 트루피크는 **−3 dBTP** 이하를 목표로 제한합니다. 재추출 때마다 평준화를 적용하며 최종 PCM의 측정치를 매니페스트에 기록합니다. 두 플레이어의 음성과 효과음이 합쳐질 때는 출력 리미터로 순간적인 과음을 줄입니다. 기존 음악·효과음 볼륨 설정은 그대로 사용할 수 있습니다. `python tools/check-audio.py`로 실제 파일의 음량·트루피크·길이를 독립 검증하고 `artifacts/audio-loudness-results.json`에 결과를 저장합니다.

메뉴 음악은 `python tools/build-menu-audio.py`로 `ost-1/`의 WebM 원본 3개에서 다시 생성합니다. 전체 약 6분 41초를 스테레오 MP3 약 8.8 MB로 저장하고 **−20 LUFS**로 평준화합니다. 원본·출력 해시, 전체 길이와 최종 음량 측정치는 `assets/menu-music.json`, 재생 순서는 `src/audio.js`의 `MENU_MUSIC`에 있습니다. 실행 파일은 `assets/audio/menu/`에서 로드하므로 원본 폴더를 배포할 필요는 없습니다.

## 검증과 빌드

```powershell
npm test
npm run check
npm run build
```

`npm test`는 Node 내장 테스트 러너로 전투 판정·잡기·공격 취소·투사체·기력·라운드·CPU·연습장과 추가 캐릭터 3명의 필살기·초필살기를 검증합니다. 원본 5개의 해시와 모든 캐릭터 에셋·음원 구간의 출처도 검사합니다. `npm run build`는 클라이언트·온라인 서버·원본 에셋을 `dist/`에 생성합니다. 온라인 서버의 방 권한·입력 동기화·재접속·재대전도 통합 테스트로 검증합니다.

브라우저 검증은 Playwright와 설치된 Microsoft Edge가 있는 환경에서 `node tools/browser-qa.mjs`를 실행합니다. Playwright가 별도 위치에 있으면 `PLAYWRIGHT_PATH`로 모듈 경로를 지정할 수 있습니다. 이 스크립트는 임시 로컬 서버를 직접 실행하고 종료하며, 화면 캡처와 결과를 `artifacts/`에 저장합니다. `node tools/matchmaking-qa.mjs`는 랜덤 연결·대기 취소·시간 초과·명시적 재시도와 화면 배치를 검증합니다. 180초 경계는 단조 증가 시계를 사용한 테스트로 확인하고, 브라우저의 시간 초과 화면은 별도 테스트 서버에서 짧은 제한으로 검증합니다. `node tools/online-qa.mjs`는 서로 다른 두 브라우저에서 온라인 대전·공유 피해·재접속·재대전과 모바일 방 화면을 검증합니다.

`npm run build:vercel` 후 `node tools/deployment-qa.mjs`를 실행하면 정적 출력물과 별도 출처의 온라인 서버를 검증합니다. 두 브라우저의 방 참가·대전·공유 피해·재접속, 허용되지 않은 출처 차단, 온라인 미설정 시 CPU·로컬 2인 플레이를 확인하고 `artifacts/deployment-results.json`에 결과를 저장합니다. 로컬 검증에서만 생성된 접속 주소 응답을 WS로 대체하며 실제 배포 주소는 WSS를 사용합니다.
